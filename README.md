# Многомерные фрактальные границы обучаемости нейросетей

Курсовая работа (продолжение НИР). СПбГУ, математико-механический факультет,
направление «Прикладная математика и информатика».
Бухаров Д. И., группа 25.Б21. Научный руководитель — проф., д.ф.-м.н. Мокаев Т. Н.

Репозиторий: https://github.com/obilka/fractal_hyperparams_project

Исследуется, сохраняется ли фрактальная структура границы обучаемости нейронной
сети при переходе от двумерного пространства скоростей обучения слоёв
(η₀, η₁) к пространству, включающему инерцию (momentum), затухание весов
(weight decay), размер мини-батча и параметры адаптивных оптимизаторов.

## Основные результаты

| Эксперимент | D_box | Комментарий |
|---|---|---|
| (η₀, η₁), tanh, 512×512 | 1.688 ± 0.035 | базовая карта, репликация |
| **(η, β), SGD+momentum, 512×512** | **1.695 ± 0.033** | инерция фрактальность не разрушает |
| (η, λ_wd) | 1.153 ± 0.035 | регуляризация сглаживает границу |
| B = 1 / 4 / 32 | 1.722 / 1.568 / 1.433 | меньше батч — изрезаннее граница |
| SGD / momentum / Adam / RMSprop | 1.633 / 1.037 / 1.322 / 1.508 | сравнение оптимизаторов |
| Adam, сечения (η, β₁) / (η, β₂) | 1.698 / 1.727 | Adam гладок не везде |
| случайные данные / digits | 1.284 / 1.494 | структура данных усложняет границу |

Теоретический результат: для L(w) = ½λw² градиентный спуск с инерцией
эквивалентен линейному отображению с матрицей
M = [[1−ηλ, −ηβ], [λ, β]], для которой det M = β, tr M = 1+β−ηλ,
откуда область устойчивости 0 < ηλ < 2(1+β) при |β| < 1 (против ηλ < 2
для обычного GD).

Главный содержательный вывод: гипотеза о сглаживании границы адаптивными
методами подтверждается лишь частично. Сглаживание обеспечивает усреднение
градиента по времени (сильнее всего — фиксированная инерция β = 0.9), а не
покоординатная нормализация, и оно является свойством выбранного сечения:
вдоль собственных осей Adam граница снова оказывается изрезанной сильнее
базовой.

## Структура проекта

```
src/fractal_hp.py        ядро: модель, оптимизаторы, сканирование сетки,
                         извлечение границы, box-counting, теоретический блок
src/run_experiments.py   все эксперименты (стадии A–H), режим возобновления
src/make_figures.py      построение всех рисунков
src/make_tables.py       генерация LaTeX-таблиц и макросов с числами
report/main.tex          отчёт (XeLaTeX)
report/sections/         разделы отчёта
report/tables/           таблицы (генерируются автоматически)
report/figures/          подпись для титульного листа
outputs/data/            результаты сканирований (.npz) и метаданные (.json)
outputs/figures/         рисунки
run_all.sh               полный цикл: расчёты → рисунки → таблицы → PDF
requirements.txt         зависимости
```

## Запуск

```bash
git clone https://github.com/obilka/fractal_hyperparams_project.git
cd fractal_hyperparams_project
pip install -r requirements.txt
bash run_all.sh
```

Отдельные стадии: `python3 src/run_experiments.py B C`.
Стадии: A — репликация с активациями, B — новые сечения (η,β), (η,λ_wd), (η,B),
C — оптимизаторы, D — данные, E — трёхмерное пространство, F — зумы,
G — точность вычислений, H — теоретический блок.

Расчёт поддерживает возобновление: результат каждого блока из 4096
конфигураций сохраняется в файл контрольной точки `*.part.npz`, повторный
запуск продолжает с места остановки, завершённые эксперименты пропускаются.

Суммарное машинное время — около 1.5 ч на одном ядре CPU.

## Технические замечания

**PyTorch не используется.** В целевой вычислительной среде он недоступен,
поэтому всё реализовано на NumPy. Ключевой приём — ансамблевая векторизация:
все узлы сетки гиперпараметров обучаются одновременно как батч независимых
сетей через `np.einsum`, что даёт ускорение примерно на два порядка по
сравнению с поэлементным циклом. Карта 512×512 при 400 итерациях считается
за 3–4 минуты на одном ядре.

**Список литературы оформлен вручную** через `thebibliography` по ГОСТ Р
7.0.100–2018, а не через `biblatex` со стилем `gost-numeric`, как рекомендует
методичка: в среде сборки отсутствуют `biber` и пакет `biblatex-gost`.
При наличии полного TeXLive список можно перевести на biblatex без изменения
содержания записей.

**Сборка через XeLaTeX**, а не pdfLaTeX: в среде отсутствуют `babel-russian`
и кодировка T2A, поэтому кириллица набирается через `polyglossia` + `fontspec`
со шрифтом Liberation Serif. Русские переносы недоступны (нет `hyph-ru`),
поэтому включён режим `\sloppy`.

**Согласованность чисел.** Все числовые значения в тексте и таблицах отчёта
подставляются автоматически из `outputs/data/*.json` через генерируемый файл
`report/tables/numbers.tex`. Расхождение между текстом, таблицами и
результатами расчётов исключено конструктивно.

## Известные ограничения

Подробно разобраны в разделе 7.4 отчёта. Кратко:

- Оценка box-counting размерности систематически зависит от разрешения сетки
  (1.511 на 128×128, 1.633 на 256×256, 1.688 на 512×512 для одной и той же
  конфигурации), поэтому сравнивать корректно только карты одного разрешения.
- Окна сканирования по η подбирались индивидуально под порог каждого метода,
  поэтому межоптимизаторное сравнение размерностей качественное.
- Переход между режимами — протяжённая зона перемешивания, а не кривая;
  значения D ≈ 1.85 на глубоких зумах отражают приближение к площадному
  заполнению.
- Критерий сходимости, унаследованный от предыдущей НИР, засчитывает как
  успех вырожденный случай «мёртвых» ReLU-нейронов.
- Box-counting на полосе (η, B) размера 512×32 не даёт достаточного числа
  масштабов, размерность по этому сечению не оценивалась.
